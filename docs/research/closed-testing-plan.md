# План: закрытое тестирование через лендинг и код приглашения

Решение владельца 2026-11-23 (после #636): **без Google Play**. APK лежит на лендинге (GitHub Pages), а закрыт **вход в приложение**: пока человек
не ввёл личный код приглашения, функции заблокированы. Код — один на человека. Дальше (подписка, Telegram) — `monetization.md`.

## Как это устроено
1. **Лендинг** (#660): статическая страница на GitHub Pages публичного `co-shell-releases` (ru/en/es): «Скачать», QR, версия, SHA-256, инструкция установки
   (Chrome, Xiaomi/HyperOS, Play Protect), «Нужен код приглашения — попросите у того, кто вас позвал». APK не прячем: без кода он бесполезен.
2. **Код приглашения** — длинная случайная строка (например `K7QX-M2PD-9WTA`, ~60 бит), хранится в Firestore `access_codes/{код}`:
   `label` (кому, для владельца), `createdAt`, `revoked`, `maxDevices`. Правила: `get` по точному id разрешён всем (как у отзывов), `list` запрещён, запись из приложения —
   только вложенная `devices/{installationId}` (создать, пока код не отозван). Угадать код нельзя, перебрать — тоже (60 бит, лимиты Firestore).
3. **Шлюз в приложении** (`app/.../access/`, `core:domain/access/`): сборки с `ACCESS_GATE` (release; debug и локальные — без шлюза).
   - Нет кода → экран «Введите код приглашения» (поле, «Продолжить», «Где взять код?»). Проверка — один запрос без входа в Google; успех — код сохраняется **на устройстве**
     и отмечается устройство (`devices/{installationId}`).
   - Код действует → всё как раньше. Перепроверка раз в 3 дня при интернете; **без сети приложение само не закрывается** (офлайн-первый) — закрывает только слово сервера.
   - Код отозван → **ввод закрыт** тем же механизмом, что «схема новее» (`gate/InputLock`, #334): данные видны, резервная копия и экспорт работают, добавлять и синхронизировать нельзя;
     окно «Доступ закрыт: обратитесь к тому, кто вас пригласил».
   - Семья владельца получает свои коды теми же командами (отдельного «исключения» нет — проще и проверяемо).
4. **Выдача и отзыв кодов** — кнопкой в GitHub Actions («Пригласить: выдать код», вход: имя; «Пригласить: отозвать код»), как `feedback.yml`: сервисный ключ
   `FIREBASE_SERVICE_ACCOUNT` уже в секретах; код печатается в сводке запуска (видно только владельцу репозитория). Агент: `agent.sh invite` — подсказка, как запустить.
   Позже — команда боту в Telegram (#662).
5. **Учёт:** по `devices` видно, сколько телефонов у кода; сверх `maxDevices` (по умолчанию 3) новое устройство не принимается.

## Чего это не даёт (честно)
- Человек с APK и без кода видит только экран кода; но APK публичен — его можно переслать. Данные и облако закрыты кодом, сам файл — нет.
- Кто получил код, может им поделиться — поэтому `maxDevices` и отзыв. Для закрытого теста с друзьями этого достаточно.
- Облачные функции (синк семьи, ИИ-разбор) позже тоже проверяют код на сервере (правила Firestore смотрят `devices`/код); в первой версии шлюз только в приложении.
