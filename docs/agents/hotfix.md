# Хотфикс: срочный выпуск исправления

Решение владельца 2026-11-19: сбой (приложение закрывается) или порча/потеря данных чинится **хотфиксом** и выпускается
сразу, мимо `dev` и кнопки релиза. Обычные ошибки — обычным путём (PR в `dev`, еженедельный релиз).

## Когда
- Отзыв «Сбой: …» (текст ошибки из `crash/CrashLog`, #218), владелец пишет «краш #N», или данные портятся/теряются.
- Берётся сразу, вне очереди; другая работа сессии ждёт.

## Путь (~20–25 мин от push до телефонов)
1. `agent.sh hotfix` — ветка сессии переезжает на `origin/main` (то, что стоит на телефонах); только с чистой веткой.
2. Unit-тест, воспроизводящий сбой, затем **минимальная** правка. Долго чинить, а виноват недавний PR — `git revert` его
   (откатить версию на телефонах нельзя: Android не ставит меньший `versionCode`, откат — тоже новая сборка).
3. `docs/whats-new.md` — новый верхний раздел `## <дата> · исправление` с `• Исправлено: …` (его покажет приложение;
   без него CI хотфикса падает). Подсказки/доски — только если правка меняет вид (обычно нет).
4. `agent.sh ship -m "Hotfix: <что чиним>" -m "Fixes #N"` — сообщение **начинается с `Hotfix:`**: по нему `auto-pr.yml` не
   открывает черновик в `dev`, а `agent.sh sync`/`update` отказываются вливать `dev`.
5. PR в **`main`** — GitHub MCP `create_pull_request` (base `main`, **черновиком**, `Fixes #N`), сразу `update_pull_request`
   `draft: false` — CI запускается на `ready_for_review` (на `opened` не запускается, `ci.md` §«Воркфлоу»). Дальше всё само:
   - `ci.yml`: `build` (`check assembleDebug`, ~5,5 мин) и `emulator` (R8 на эмуляторе, ~15 мин) параллельно;
   - задача `hotfix` (оба зелёные) → `scripts/ci/automerge.sh` вливает PR в `main` merge-коммитом (версия — следующий минор,
     `version_name.py`), закрывает `Fixes #N`, запускает CI на `main` — он публикует сборку, телефоны видят «Обновить»;
   - `scripts/ci/backmerge.sh` вливает `main` в `dev` (PR `backmerge/hotfix-N`, сразу); `whats-new.md` сливается `union` —
     невыпущенный раздел `dev` остаётся сверху. Конфликт в другом файле — комментарий в PR хотфикса, слить руками.
6. Метка `hold` на PR — остановить. Упал CI/эмулятор — чинить в той же ветке, push перезапускает.

## Признак хотфикса в CI
PR в `main` не из `dev` (`github.base_ref == 'main' && github.head_ref != 'dev'`); сливается, только если ветка агента
(`claude/*`, `ccr-*`) или `hotfix/*`. Релизный PR `dev → main` по-прежнему вливает только кнопка (`release.yml`).

## Ограничения
- Всё это работает из копии файлов в `main`: `ci.yml`, `auto-pr.yml` и скрипты хотфикса действуют после ближайшего релиза.
- Тесты: `scripts/ci/test_automerge.py` (хотфикс ждёт задачу `hotfix`, вливает, зовёт `backmerge.sh`).
