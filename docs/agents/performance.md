# Производительность: лёгкое, быстрое, плавное

Требование владельца (2026-11-08): приложение лёгкое, экономит оперативную память, быстро отвечает
и плавно анимируется, в том числе на экранах 90/120 Гц. Правила ниже обязательны для нового кода.

## Бюджеты (цели, проверяем на release-сборке)
| Метрика | Цель |
|---|---|
| Холодный запуск до первого кадра «Обзора» | < 500 мс на телефоне владельца |
| Кадр при прокрутке и анимации | без пропусков на 120 Гц (кадр ≤ 8 мс) |
| Память (PSS) на главных экранах | < 150 МБ |
| Размер release APK | < 15 МБ; новая зависимость > 500 КБ — только с обоснованием в ARCHITECTURE |

## Зависимости и размер
- Новая библиотека — только если своё решение заметно сложнее. Предпочтение — AndroidX/Kotlin.
- Release: R8 + `isShrinkResources` (включены). Новая библиотека → проверить keep-правила.
- Картинки — векторные (`drawable/*.xml`), без растровых ресурсов и шрифтов «на всякий случай».

## Данные и память
- Тяжёлое — не в главном потоке: Room, файлы, сеть — `suspend`/`Flow` на `Dispatchers.IO`/`Default`.
- Суммы, итоги, группировки считает **SQL** (агрегаты), а не загрузка всех строк в память.
- Длинные списки — постранично: `GrowingWindow` (`TransactionFilter.limit`) + `LoadMoreEffect` у `LazyColumn`.
- `stateIn(viewModelScope, SharingStarted.WhileSubscribed(5_000), …)` — потоки не работают в фоне.
- **Перед `stateIn` — `.offMain()`** (`ui/StateWork.kt`, #258): иначе `combine`/`map` и маппинг Room идут в главном
  потоке. В тестах `MainDispatcherRule` делает его синхронным.
- Курсы: `observeRates()` — один общий поток на приложение (#260), книга — `RateBook.of(list)`, не `RateBook(list)`.
- Фильтры списков — в SQL; в памяти только поиск по тексту, и Room перезапрашивается лишь при смене SQL-части (#261).
- Без утечек: никаких ссылок на `Activity`/`Context` в синглтонах и ViewModel.

## Compose: меньше перерисовок
- UiState — неизменяемые `data class`, списки — `kotlinx.collections.immutable`
  (`ImmutableList`) или классы, которые компилятор Compose считает стабильными.
- Форматирование сумм и дат — во ViewModel (уже правило `code-style.md`), не в `@Composable`.
- `LazyColumn`: всегда `key = { it.id }` и `contentType` для разных типов строк.
- Частые значения (прокрутка, анимация) читаем в лямбдах: `Modifier.offset { }`,
  `graphicsLayer { }`, `drawBehind { }` — тогда меняется только отрисовка, без рекомпозиции.
- `derivedStateOf` — для условий от прокрутки (показать кнопку «наверх» и т.п.).
- `remember` для дорогих объектов (`Path`, кисти графиков); не создавать их в каждом кадре.

## Анимации
- Анимируем дешёвое: `alpha`, `translation`, `scale` через `graphicsLayer`. Размер раскладки (#64) —
  только примитивами `core:designsystem/motion/Resize.kt`: перерасчёт раскладки идёт лишь пока блок меняет
  размер (~300 мс), в покое — бесплатно. Не анимировать размер целых экранов и длинных списков (там — `listItemMotion`).
- Длительности и кривые — общие токены движения дизайн-системы (`core:designsystem`), не числа
  в экранах. Переходы между экранами — единые в `navigation/`.
- Частоту кадров не задаём вручную: Compose рисует на частоте экрана; задача — уложиться в кадр.
- Уважать системную настройку «Убрать анимации» (масштаб анимации 0).

## Как проверять
- Профиль запуска: `app/src/main/baseline-prof.txt` — шаблон на весь `app/coshell/**` (#263), библиотеки дают свои;
  ставит `profileinstaller`. Замеренный профиль (макробенчмарк) — когда будет эмулятор/телефон (#149).
- Размер (2026-11-12): release APK 5,5 МБ (было 8,0); ~2,5 МБ — встроенный SQLite (arm64 + armv7, #264).
- Отчёты компилятора Compose (`composeCompiler { reportsDestination }`) — искать нестабильные классы.
- На телефоне: «Для разработчиков → Профилировать HWUI → столбцы», Android Studio Profiler (память).
- Объём: `scripts/agent/agent.sh scale` — импорт/список/синк/размер БД на 10 000 операций (`ImportScaleTest`,
  цифры — `notes.md`); `agent.sh wallet` — такая же выгрузка для импорта на телефоне.
- Пакетные записи в Room — одной транзакцией (`@Transaction`), не построчно: каждый коммит — fsync
  и пересчёт всех `Flow` по таблице.
- Тормоза на телефоне — записывать в STATUS с экраном и действием.
