# Закрытое тестирование: коды приглашения

Полный порядок включения со ссылками — `closed-test.md` (кнопка выдачи кодов появляется только после релиза, где `invite.yml` попадает в `main`).

Как выдать человеку доступ и как его закрыть. Устройство — `docs/research/closed-testing-plan.md`. Сделать нужно один раз (шаги 1–3), дальше — шаг 4.

## 1. Правила Firestore
Ничего делать не нужно: правила для кодов (`access_codes`) публикует CI после мержа в `dev` (`docs/agents/ci.md` §«Правила Firebase»).
Проверить: Firebase Console → Firestore → Rules — в тексте есть `match /access_codes/{code}`.

## 2. Секрет и переменная (уже есть, если работают «Отзывы»)
- Секрет `FIREBASE_SERVICE_ACCOUNT` (Settings → Secrets and variables → Actions) — ключ сервисного аккаунта, роль «Cloud Datastore User».
  Если «Отзывы из приложения → задачи» работают, ключ уже на месте.
- Переменная `FIREBASE_PROJECT_ID` (там же, вкладка Variables) — как для сборки приложения.

## 3. Включить шлюз в приложении (только когда готовы раздавать коды!)
Шлюз по умолчанию **выключен**. Пока переменная не задана, приложение открыто всем, как раньше.
1. Settings → Secrets and variables → Actions → Variables → **New repository variable**: имя `ACCESS_GATE`, значение `true`.
2. Выпустить релиз («Релиз: выкатить dev на телефоны»). Первый запуск после обновления попросит код — у всех, включая вашу семью.
3. **До** релиза со шлюзом выдайте коды себе и семье (шаг 4; кнопка есть после первого релиза без шлюза) и сохраните их: без кода приложение после обновления не откроется. Данные при этом не пропадают.
Выключить обратно: переменная `ACCESS_GATE` = `false` (или удалить) и новый релиз.

## 4. Выдать, отозвать, посмотреть
**Actions → «Приглашения: коды для закрытого теста» → Run workflow**:
- **выдать код** — «Выдать: для кого» (имя, как вам удобно) и «сколько телефонов» (по умолчанию 3) → код в сводке запуска (`Summary` внизу страницы запуска), вида `K7QX-M2PD-9WTA`.
  Передайте его человеку лично, не в общем чате.
- **отозвать код** — «Отозвать: код». Приложение закроет ввод при следующей проверке (раз в 3 дня при интернете, и при каждом открытии, если пора).
- **показать все коды** — кому выдан, действует ли, на скольких телефонах стоит.
Из консоли: `gh workflow run invite.yml -f action='выдать код' -f name='Аня'` (подсказка — `scripts/agent/agent.sh invite`).

## Что видит человек
Установил APK с лендинга → «Co-Shell для приглашённых» → вводит код (один раз, нужен интернет) → дальше всё работает без интернета. Код ввёл на четвёртом телефоне при лимите 3 —
«Код уже стоит на всех телефонах…»: выдайте новый или отзовите старый.

## Ограничения
APK публичен и его можно переслать; без кода внутри ничего не открыть. Код можно передать другому — поэтому лимит телефонов и отзыв.
