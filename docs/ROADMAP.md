# План разработки co-shell

Каждый этап заканчивается рабочим APK, который можно поставить на телефон.

## Этап 0. Основа
- [x] Android-проект: Kotlin, Compose, Hilt, version catalog, модули `app`, `core:model` (KMP), `core:designsystem`
- [x] Design system: тема (светлая/тёмная), цвета сумм, типографика
- [x] `Money` и `CurrencyInfo` (минимальные единицы, форматирование, парсинг ввода) + тесты
- [x] CI в GitHub Actions: lint, unit-тесты, debug APK как артефакт сборки
- [x] `AGENTS.md` + тематические правила в `docs/agents/`

## Этап 1. Локальная версия (без сети) — готово
- [x] Room: Account, Category, Transaction, Budget + стратегия миграций
- [x] Счета в разных валютах, баланс каждого счёта (список, создание/редактирование, архив, удаление)
- [x] Навигация (Navigation Compose, type-safe routes) и нижняя панель
- [x] Набор категорий по умолчанию, редактирование категорий: добавить, переименовать, удалить/архив, папки (группы)
- [x] Цвет и иконка категории в редакторе
- [x] Быстрый ввод операции (сумма → категория → сохранить), с возможностью сменить дату
- [x] Список операций с группировкой по дням, редактирование, удаление
- [x] Переводы между счетами, включая обмен валют (две суммы)
- [x] Экспорт/импорт JSON (резервная копия на случай переустановки): «Ещё → Резервная копия»
- [x] Первый запуск на телефоне владельца, проверка по чек-листу (в т.ч. копия на Google Диск)

**Результат:** одним человеком уже можно пользоваться.

## Этап 2. Доставка и самообновление
- [ ] Firebase-проект (Spark), проверка доступности сервисов в регионе
- [ ] Ключ подписи release, хранение в GitHub Secrets + резервная копия у владельца
- [ ] CI: автоматический versionCode (✓ сделан — номер запуска CI; debug APK уже в GitHub Releases), подписанный APK, выкладка в Firebase Hosting + `version.json`
- [ ] В приложении: проверка обновлений (при запуске и раз в сутки), экран «что нового»
- [ ] Загрузка APK, проверка SHA-256, установка через PackageInstaller
- [ ] Первая установка на оба телефона

**Результат:** дальше каждое изменение приходит на телефоны само.

## Этап 3. Мультивалютность
- [ ] `RatesProvider` + основной и резервный источники, кэш в Room, ежедневное обновление через WorkManager
- [ ] Ручная правка курса
- [ ] `CurrencyConverter` (курс на дату, ближайшая дата, кросс-курс) + тесты
- [ ] Настройка валют отчётов, смена основной валюты
- [ ] Главный экран: общий баланс и траты за месяц в основной (и дополнительных) валютах
- [ ] Траты в валюте, отличной от валюты счёта

## Этап 4. Синхронизация на двоих
- [ ] Firebase Auth по email/паролю
- [ ] Создание семьи и добавление второго участника (код-приглашение)
- [ ] Security rules: доступ только участникам семьи + тесты правил в эмуляторе
- [ ] SyncEngine: очередь `pendingSync`, push/pull, realtime listener, tombstones, last-write-wins
- [ ] Тесты конфликтов и офлайн-сценариев (два эмулятора)
- [ ] Автор операции в списке, общие и личные счета
- [ ] Автоматическая еженедельная резервная копия в выбранную папку

**Результат:** оба телефона видят общий бюджет и работают офлайн.

## Этап 5. Переезд из Wallet
- [x] Получить образец CSV-экспорта из Wallet, зафиксировать формат и тестовые файлы
- [ ] Парсер CSV (чистый Kotlin) + тесты на образцах
- [ ] Мастер импорта: сводка → сопоставление счетов и категорий → предпросмотр → импорт
- [ ] Склейка переводов (две записи Wallet → один transfer), исторические курсы → ManualRate
- [ ] Защита от дублей при повторном импорте
- [ ] Финальный переезд: сверка балансов счетов с Wallet

**Результат:** вся история в co-shell, Wallet можно отключать.

## Этап 6. Бюджеты и аналитика
- [ ] Месячные лимиты по категориям (в своей валюте), прогресс
- [ ] Отчёты: структура трат, динамика по месяцам, по участникам — в выбранной валюте
- [ ] Фильтры и поиск
- [ ] Уведомление о приближении к лимиту

## Этап 7. Удобства
- [ ] Регулярные платежи (подписки, коммуналка)
- [ ] Виджет быстрого ввода
- [ ] Блокировка по PIN / биометрии
- [ ] Экспорт в CSV
- [ ] Обратная связь из приложения → issue на GitHub → разбор агентом (схема — в «Идеях на потом»)

## Идеи на потом
- Автоввод операций (Т-Банк, Ameriabank, Google Wallet — по push-уведомлениям; Bybit — по API; выписки — для сверки),
  см. `docs/research/auto-import-banks.md`. Кандидат на этап после синхронизации.
- **Обратная связь → GitHub issue → агент.** Токен GitHub в APK не кладём (APK лежит публично на Hosting).
  Схема: форма в «Ещё»: пользователь пишет **только текст**, приложение само добавляет служебное (версия, модель телефона, Android, id установки) → документ в Firestore `feedback`
  (после этапа 4) → GitHub Action по расписанию создаёт issue токеном из Secrets и помечает документ
  обработанным → агент (Claude Code GitHub Action по метке) разбирает issue и открывает PR, владелец
  проверяет и мержит. Cloud Functions не нужны (они требуют платный тариф Blaze).
- Чеки по QR
- Цели накоплений
- Kotlin Multiplatform для iOS (domain и model уже на чистом Kotlin)
