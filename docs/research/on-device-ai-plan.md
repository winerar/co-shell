# ИИ на телефоне: лицензии и «оболочка» вокруг модели (2026-11-21)

Часть истории #583 (`on-device-ai.md` — исследование и замеры). Здесь — что можно распространять и как сделать, чтобы модель работала быстрее и точнее.

## Лицензии: можно ли включать модели в бесплатное (и платное) приложение
Проверено по карточкам моделей на Hugging Face и тексту Gemma Terms of Use (2026-11-21). Это не юридическая консультация; перед магазином — перечитать.
| Модель | Лицензия | Коммерческое использование | Раздавать из приложения | Условия |
|---|---|---|---|---|
| Qwen 3 / Qwen 3.5 (0,6B–4B) | **Apache 2.0** | да, без платы и ограничений | да | приложить текст лицензии и NOTICE, пометить свои изменения |
| **Gemma 4** (E2B, E4B) | **Apache 2.0** (карточка `litert-community/gemma-4-*-litert-lm`) | да | да | как у Apache 2.0 |
| Gemma 3 / Gemma 3n | **Gemma Terms of Use** (своя) | да, платы и порога по доходу нет | да, но с условиями | в условия приложения включить запреты из Prohibited Use Policy; дать получателю копию условий; файл Notice «Gemma is provided under and subject to the Gemma Terms of Use found at gemma.ai/resources/terms»; Google оставляет за собой право ограничить использование |
- **Бесплатная версия без денег за ИИ — можно** по любой из этих лицензий: платы за использование нет ни у одной. Условия Gemma 3/3n — про оформление, не про деньги.
- Проще всего **Qwen 3.5 и Gemma 4 (Apache 2.0)**: лицензия не требует вставлять запреты в наши условия. Gemma 3n закрыта на Hugging Face (нужны аккаунт, принятые условия и токен) — для обычного пользователя скачивание «одной кнопкой» невозможно, пока файл не лежит у нас (а тогда действуют условия Gemma).
- Выпуск моделей — как выпуск стороннего ПО: экран «О приложении → Лицензии» со списком (модель, автор, лицензия, ссылка); для Apache 2.0 — копия текста.
- Скачивание с Hugging Face напрямую из приложения не требует нашего хостинга, но завязывает нас на их адреса: хранить ссылку и контрольную сумму в конфиге, при смене — обновление приложения.

## «Оболочка»: как помочь модели работать быстрее и точнее
Принцип: **код делает всё, что может, модель — только остаток**, и человек всё проверяет (ИИ предзаполняет, сохраняет человек).
1. **Правила первыми** (`core:domain`, без ИИ): сумма («24000», «30к», «3 500», «6,99 usd»), дата («вчера», «позавчера», «ayer»), число словами ru/es/en, валюта, счёт по слову («карта», «наличные»), название. Строка «овощи 12000» полностью разобрана кодом — модель не запускается вовсе (экономия времени и батареи).
2. **Модель получает только неясное**: непонятное слово → нормализованное название, категория, строка, которую код не разобрал. Меньше токенов — быстрее и точнее.
3. **История семьи вместо знаний модели**: категория по уже виденным получателям — частоты (`CategoryGuess`, #584); модели для нового получателя в запрос кладём 15–20 **похожих** прошлых записей семьи («Disco → Продукты»). Замер подсказки 20 случайными примерами (`ai_eval.py --fewshot 20`): Qwen 3 1,7B 20 % → 30 %, Gemma 3 4B 61 % → 63 % — прирост малый: примеры были не похожие на спрашиваемого получателя, а модель не знает бренд. Идея владельца (2026-11-21) — **словарь популярных брендов и видов мест**: сделан кодом (`BrandDictionary`, ~700 названий: Аргентина, Россия, мир; на списке из набора находит ≥ 90 % — оценка завышена, словарь писали, видя список). Вывод: для **нового** получателя ИИ не угадывает — не подставлять, спросить человека (недавние категории первыми, как сейчас); ИИ-категория (#594) остаётся выключенной.
4. **Выбор из списка, а не свободный текст**: ответ — одна из категорий пользователя или «не знаю» (допустимые значения заданы в запросе; ответ вне списка отбрасывается). Если LiteRT-LM умеет ограниченное декодирование (формат вызова инструмента с перечислением) — включить; иначе строгий разбор JSON и повтор один раз.
5. **Проверка ответа кодом**: число из ответа обязано встречаться в тексте (иначе поле пустое), дата — в разумном окне, валюта — из списка, сумма чека = сумма товаров ± скидка; расхождение — пометка «проверьте», не молчаливая запись.
6. **Пакетом**: все строки заметок — одним запросом (массив JSON), а не по одному: системная часть запроса префиллится один раз; один вызов на 10 строк вместо десяти.
7. **Жизненный цикл**: модель грузится по первому «Обработать»/микрофону, выгружается через ~60 с простоя; не запускать при экономии заряда и сильном нагреве; прогресс и «Отменить» всегда; без блокировки ввода (категория подставляется, когда ответ готов, если человек не выбрал сам).
8. **Выбор модели по телефону**: память (слабый/средний/сильный, `on-device-ai.md`) + быстрая проверка скорости при установке (≈10 с, «Проверить скорость»): медленный телефон — меньшая модель или только правила; GPU там, где работает, иначе процессор.
9. **Без ИИ всё работает**: правила (п. 1) и история (п. 3) — полноценный режим; ИИ — улучшение.
10. **Регрессия**: набор `docs/samples/ai/eval.json` и `ai_eval.py` (ПК), на телефоне — приложение замера `tools/aibench` (те же примеры). Прирост «оболочки» измеряем теми же числами до включения.
