# Тексты интерфейса

Как писать строки UI. Приложение может быть опубликовано (владелец 2026-11-14) — тексты пишем так,
чтобы их можно было перевести и показать незнакомому человеку. Ревизия всех строк — 2026-11-14.

## Где живут
- **Все строки UI — в ресурсах** (до публикации — только русский, en/es позже: `glossary.md` §«Языки») `app/src/main/res/values/strings*.xml` (файл на тему: `strings_budgets.xml`…).
  В Kotlin — только `stringResource(R.string.…)`; литералы на русском допустимы в `*Previews.kt`, `*Samples.kt`,
  каталогах дизайн-системы и тестах. Поиск нарушений: `grep -rnP '"[^"]*[А-Яа-яЁё]' app/src/main --include=*.kt`.
- `core:model`/`core:domain` текстов не показывают: отдают коды/enum, текст выбирает `app`. Исключение —
  данные, которые приложение создаёт само (стандартные категории, «Корректировка баланса»): имена приходят
  через `CategoryNames` из `strings_defaults.xml` (`categories/ResourceCategoryNames.kt`).
- Слово-подтверждение стирания — ресурс `wipe_confirm_word` (при переводе меняется вместе с языком).
- Чисто форматные строки (`%1$s · %2$s`, `1 %1$s = …`), название, атрибуция — `translatable="false"`.
- Язык интерфейса задаёт `language/AppLanguage.kt` (сейчас только `ru`). Новый язык = `values-xx/strings*.xml`
  + тег в `SUPPORTED`.

## Как писать
- **Главное (владелец 2026-11-15): лаконично, дружелюбно, уважительно — во всём интерфейсе.** Даже новичку в ведении
  бюджета должно быть понятно, **что где и как делается, почему так называется и где найти нужное**. На практике:
  незнакомое слово объясняем там, где его встречают впервые (пустой экран, подсказка: «Тег — цветная метка операции…»);
  отсылаем путём («Ещё → Категории»), а не «в настройках»; называем действие, а не механизм («Курс посчитается сам»).
- **Значок говорит сам (владелец 2026-11-25):** понятный значок («✕», корзина, лупа, «+») подписью не дублируем; подпись — только для TalkBack.
  Не пишем пояснений, которые ничего не добавляют (счётчики «· 5 историй», «как удобно», повтор заголовка в тексте). Сомневаешься — убери.
- **Коротко.** Кнопка — 1–2 слова, глагол в инфинитиве («Сохранить», «Отменить импорт»). Чип/плитка/подпись
  поля — 1–2 слова. Подсказка под элементом — одна строка (~40 знаков на 390 dp). Описание — 1–2 предложения.
- **Сначала суть, потом причина:** «Валюту не изменить: по счёту есть операции», а не наоборот.
- **Без внутренней кухни:** не упоминать Firebase, GitHub, «задачу разработки», «журнал обновления».
  Ошибка сервера — «Ошибка сервера (код)», лимит — «Дневной лимит синхронизации».
- **Без привязки к нашей семье:** не «оба телефона»/«второй телефон» — «все/другие телефоны»; не «на двоих» / «for two» / «para dos» (в семье до 10 человек) — «общий бюджет семьи», «с близкими»;
  не «загрузить Wallet» вне экрана импорта; в примерах — не имена людей.
- **Действие жестом — «Нажмите»/«Удерживайте»**, не «тап»/«удержание». Схема «Нажмите — X, удерживайте — Y».
- Обращение на «вы» со строчной, без восклицаний (кроме «Спасибо!»). Ошибки — что случилось + что делать:
  «Не удалось скачать. Проверьте интернет и повторите.»
- Пустой экран: «Операций пока нет. Нажмите «+», чтобы добавить первую.»
- Подтверждение удаления (там, где нет «Отменить»: шаблон, долг): заголовок-вопрос «Удалить шаблон?», текст — последствие («Шаблон удалится навсегда.»). Счёт, категория и операция удаляются сразу, снэкбар «Счёт удалён · Отменить» (#194).
- Без сокращений с точкой («Нач.», «заблок.») — лучше короче по смыслу.

## Типографика и формат
- Кавычки «ёлочки», тире « — » (с пробелами), диапазон «3–10» (короткое без пробелов), многоточие «…»,
  разделитель в строке « · », стрелки «→» в путях («Ещё → Категории»).
- Плейсхолдеры нумерованные: `%1$s`, `%2$d`. Числа со словом — `<plurals>` (ru: one/few/many/other) или форма
  «Слово: N» («Удалено операций: 3»), не «среди %d категорий».
- Названия экранов в кавычках так же, как в меню: «Ещё → Резервная копия».
