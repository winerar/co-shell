# Деньги и валюты

## Хранение
- Сумма = `Money(amountMinor: Long, currency: CurrencyCode)`. Минимальные единицы: копейки, центы, сатоши.
- Число знаков после запятой — `Currencies.info(code).fractionDigits` (JPY 0, RUB 2, KWD 3, BTC 8).
  Неизвестный ISO-код → 2.
- В Room: две колонки `amount_minor INTEGER` + `currency TEXT`. В Firestore — так же (`Long` + строка).
- `Double`/`Float` для денег запрещены везде, включая промежуточные вычисления.

## Арифметика
- `+`, `-`, сравнение — только в одной валюте, иначе `IllegalArgumentException`.
- Переполнение → `ArithmeticException` (никакого тихого переноса).
- Доля суммы — `money.scale(числитель, знаменатель)`: 128-битное произведение, округление HALF_EVEN (темп бюджета
  по дням, среднее за месяцы). Распределение с остатком (появится позже) — отдельная функция с явным правилом.

## Ввод и вывод
- Ввод пользователя → `MoneyParser.parse(text, currency)`: пробелы игнорируются, `,` и `.` распознаются
  как разделители, лишние знаки после запятой — ошибка `TOO_MANY_FRACTION_DIGITS`, а не округление.
- Вывод → `MoneyFormat` (`RU`: «1 234,56 RUB», `EN`: «1,234.56 USD»; всегда буквенный код после числа, символов нет — issue #61). Форматирование только в ViewModel/UI-слое.

## Мультивалютность (подробности — ARCHITECTURE §6)
- Факты хранятся в исходной валюте; конвертация — только при показе, по курсу на дату операции.
- Смена основной валюты не меняет данные, только представление. Валюты отчётов — `ReportCurrencySettings`
  (`core:domain/settings/`, первая — основная, не пустой список, по умолчанию USD).
- Итог балансов — `RateBook.balanceTotals` (по курсу на сегодня): сначала сумма по валюте, потом один
  пересчёт; валюты без курса — в `missing`, в итог не входят.
- Курс — `Rate` (`core:model`): мантисса `Long` + масштаб, до 15 значащих цифр и 18 знаков после
  запятой, только положительный. Хранение — строкой (`toPlainString` / `Rate.parse`).
  Пересчёт суммы — `rate.convert(money, to)`: 128-битное промежуточное умножение (`WideMath.kt`),
  округление HALF_EVEN до минимальной единицы целевой валюты. `times`/`inverse` — кросс и обратный курс.
- Запись курса — `ExchangeRate(date, from, to, rate, origin)`, `origin` = `MANUAL` (ручной, синхронизируется)
  или `DOWNLOADED` (кэш). `1 from = rate to`; одна запись обслуживает и обратное направление.
- Поиск курса — `core:domain/rates/RateBook`: ручной курс пары на дату или раньше (действует до следующего
  ручного) → загруженный на дату или ближайший ранее → кросс через USD → ближайший позже.
  Пересчёт для показа — `CurrencyConverter` (`convert`, `total` со списком валют без курса).
- Хранение курсов — `ExchangeRateRepository` (таблицы и правила — `database.md` §«Курсы»).
- Обмен валют — перевод между счетами с двумя суммами (`amountMinor` и `toAmountMinor`).
- Покупка в другой валюте (чек в ARS, списано с USDT-карты) — расход/доход с `originalAmount`:
  `amount` = списано (в валюте счёта, меняет баланс), `originalAmount` = сумма чека (для отчётов).
  Валюта чека ≠ валюта счёта, у переводов чека нет (`SaveTransactionUseCase`). Курс покупки —
  `Rate.between(списано, чек)`, на экране — `receiptRateText` (направление, где число ≥ 1).
