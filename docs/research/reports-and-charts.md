# Отчёты и графики: какие диаграммы и почему

Исследование к этапу 6 (2026-11-08). Цель — выбирать вид графика не «как красивее», а по данным
исследований восприятия. Источники — в конце; номера в скобках ссылаются на них.

## 1. Главный принцип: точность чтения
Люди сравнивают величины с разной точностью в зависимости от способа кодирования [1, 2]
(от точного к грубому):
1. **положение на общей шкале** (точки, концы столбцов на одной оси);
2. положение на несовмещённых шкалах (small multiples);
3. **длина**, наклон, угол;
4. площадь;
5. объём, кривизна, насыщенность и оттенок цвета.

Вывод: всё, где важно **сравнить** суммы, рисуем столбцами/линиями от общей оси. Площадь и цвет —
только для «картинки в целом» или как второй признак.

## 2. Выбор графика под вопрос
| Вопрос пользователя | График | Почему |
|---|---|---|
| На что ушли деньги за месяц? | **Горизонтальные столбцы** по категориям, по убыванию, подписи сумм и % | длина на общей оси [1, 2]; длинные русские названия влезают слева; сортировка — сразу видно главное |
| Какая доля у топ-категорий? | **Кольцо (donut)** — максимум 5–6 сегментов + «Другое», в центре итог | для «часть от целого» круг не хуже столбцов [3, 4]; кольцо читается так же, как круг [5]; но только как обзор, не для точного сравнения |
| Как меняются траты по месяцам? | **Столбцы по месяцам** (≤ 12–13), линия — если точек много (дни, > 13 месяцев) | столбцы — сравнение дискретных значений, линия — тренд [6] |
| Укладываюсь ли в бюджет? | **Bullet graph / полоса прогресса** с отметкой «темп на сегодня» | придуман как компактная замена спидометрам [7]; длина + метка на одной шкале |
| Доходы против расходов, накопления | Парные столбцы по месяцам + линия «остаток»; итог месяца — число | сравнение двух рядов на общей оси |
| Как менялся капитал (все счета)? | **Линия** (net worth) в основной валюте | непрерывный тренд [6] |
| Структура по папкам → категориям | Столбцы с раскрытием папки по тапу (не treemap) | treemap точен хуже столбцов [8]; иерархия у нас всего 1 уровень |
| Кто сколько потратил (2 участника) | Сложенная полоса 100% или два столбца | две величины — сравнение тривиально |

**Не используем:** 3D, «объёмные» круги, спидометры, круг с > 6 сегментами, радар-диаграммы.

## 3. Правила отрисовки
- **Столбцы — всегда от нуля.** Обрезанная ось у столбцов преувеличивает разницу [9, 10]. У линий
  ось можно не начинать с нуля, но это явно видно по подписям.
- **Мало категорий на экране:** 5–7 + «Другое» (рабочая память ≈ 4 элемента [11]).
- **Сортировка по величине**, а не по алфавиту (кроме оси времени).
- **Подписи прямо на графике** (сумма у столбца), легенда — только если без неё никак.
  Минимум «чернил не про данные»: без фоновой сетки-клетки, теней, градиентов [12].
  Украшения повышают запоминаемость, но не точность [13, 14] — для учёта важна точность.
- **Цвет:** категории уже имеют свои цвета (`CategoryBadge`) — используем их, но никогда не делаем цвет
  единственным признаком: подпись/иконка рядом. ~8% мужчин различают цвета хуже [15] — проверять
  контраст и не ставить рядом красный/зелёный как единственное различие.
  Расход/доход — существующие цвета сумм из design system.
- **Одна валюта на графике** — основная (или выбранная); пересчёт по курсу на дату операции
  (этап 3, `CurrencyConverter`), рядом подпись «в USD по курсу на дату операции».
- **Тап по элементу** → список операций, из которых он сложился (доверие к цифре). Долгий тап /
  подсказка — точная сумма.
- **Сравнение с прошлым периодом** — тонкая метка/призрачный столбец, а не второй график.
- Пустые данные — понятное состояние «Нет операций за период», а не пустая ось.
- Доступность: у графика есть текстовое описание для TalkBack (итог + топ-3).

## 4. Пользовательские отчёты
Конструктор не «всё со всем», а из небольшого набора осей — иначе легко получить нечитаемый график.
- **Что:** расходы / доходы / оба / остаток / капитал.
- **Группировка:** категория, папка, счёт, участник, месяц / неделя / день.
- **Фильтр:** период (месяц, квартал, год, свой), счета, категории, участник, заметка содержит…
- **Валюта:** основная или любая из списка валют отчётов.
- **Вид графика выбирается автоматически** по таблице §2 (время → столбцы/линия, категории → полосы,
  доля → кольцо); ручная смена — только среди допустимых вариантов.
- Отчёт сохраняется под именем и появляется на вкладке «Отчёты»; можно закрепить на «Обзор».
- Хранение: настройки отчёта в Room (локально; в Firestore — по желанию на этапе 4), сам отчёт
  считается SQL-агрегатами + пересчётом валют в `core:domain` (чистый Kotlin).
- Под графиком — таблица с теми же числами (то, что нельзя точно прочитать с графика).

## 5. Реализация (кандидаты, решить при старте этапа)
- Столбцы, полосы, кольцо, bullet — своим Canvas в Compose (простые формы, полный контроль над
  правилами выше, без зависимости). Общие компоненты в `core:designsystem` (`charts/`).
- Линии с прокруткой и масштабом — рассмотреть библиотеку **Vico** (Compose-native); проверить
  поддержку Compose Multiplatform и размер.
- Расчёты (группировка, доли, «Другое», темп бюджета) — в `core:domain`, с unit-тестами.
