# Исследование: автоматический ввод операций из Ameriabank, Bybit, Т-Банка, Google Pay

**Дата:** 2026-11-08 · **Статус:** исследование, решение не принято (см. «Рекомендация»).

Вопрос: можно ли, чтобы операции из приложений Ameriabank (MyAmeria), Bybit, Т-Банка и Google Pay
появлялись в co-shell сами, без ручного ввода, при ограничениях проекта: бесплатно, без своего
сервера, офлайн-first, APK вне магазинов, 2 Android-телефона.

## Итог в одной таблице

| Источник | Официальный API для физлица | Push/SMS на телефоне | Файл выписки | Лучший путь |
|---|---|---|---|---|
| **Ameriabank** | нет (API есть только для бизнеса, платно) | да (push MyAmeria, SMS-оповещения) | PDF/Excel из интернет-банка — **формат проверить** | уведомления + импорт выписки для сверки |
| **Bybit** | **да**: REST API v5, ключ «только чтение» | push приложения Bybit | CSV из веб-версии | API (с телефона), уведомления — запасной вариант |
| **Т-Банк** | нет для обычных счетов/карт (есть Invest API — только брокерский счёт; T-API — только бизнес) | да (бесплатные push сохраняются) | выписка в веб-версии (PDF/Excel/CSV — **формат проверить**) | уведомления + импорт выписки для сверки |
| **Google Pay / Wallet** | нет (Google Wallet API — только для выпуска карт/пропусков, не для чтения операций) | да (уведомление Wallet после оплаты телефоном) | Google Takeout (вручную, JSON — **проверить**) | уведомления Wallet как **дополнительный** источник к push банков |

Короткий ответ: **да, можно**, но универсального «банковского API» для физлиц нет ни в Армении,
ни в России. Реально работающая схема — три механизма, которые дополняют друг друга:
1. **Чтение уведомлений банковских приложений на телефоне** (`NotificationListenerService`) —
   почти мгновенно, работает для всех трёх, без сети и серверов.
2. **API Bybit** — точные данные по крипто-счёту и карте Bybit.
3. **Импорт файлов выписок** — раз в месяц для сверки и добора пропущенного.

## 1. Механизмы на Android (общие для всех банков)

### 1.1 Чтение уведомлений — `NotificationListenerService` (рекомендуется)
- Пользователь один раз включает доступ: «Настройки → Уведомления → Доступ к уведомлениям».
  Разрешение не «опасное», на sideload-APK ограничений Google Play нет.
- Сервис получает `StatusBarNotification` с `packageName`, `EXTRA_TITLE`, `EXTRA_TEXT`,
  `EXTRA_BIG_TEXT`, временем. Фильтруем по пакетам банков, текст разбираем правилами (regex).
- Плюсы: мгновенно, офлайн, бесплатно, не нужен логин в банк, не зависит от API банка.
  Так работают многие трекеры трат (например, режим «по уведомлениям» в сторонних приложениях).
- Минусы и риски:
  - формат текста меняется без предупреждения → парсеры должны быть версионируемыми и покрыты
    тестами на реальных образцах; нераспознанное — в «Входящие» на ручной разбор, а не в мусор;
  - пропуски: уведомление не пришло/смахнули до доставки/телефон выключен, банк не шлёт push о
    части операций (комиссии, проценты, кэшбэк) → нужна периодическая сверка с выпиской;
  - отключение агрессивной оптимизацией батареи (Xiaomi, Huawei и т.п.) → инструкция и проверка
    `isNotificationListenerAccessGranted`, `requestRebind`;
  - на одном телефоне — операции только того, у кого этот банк. Это нормально: запись уходит в
    Room → Firestore → второй телефон.
- Код: сервис и доступ к Android — в `app`/`core:data`; **парсеры текста — чистый Kotlin**
  (`core:importer`, `commonMain`) — тестируются на JVM и переживут переход на KMP.
  На iOS аналога нет (чужие уведомления читать нельзя) — там только API/файлы.

### 1.2 Чтение SMS (запасной вариант)
- `READ_SMS`/`RECEIVE_SMS` — для sideload-APK можно. Полезно, если push выключены, а SMS включены.
- Минусы: SMS-оповещения у банков часто платные (у Т-Банка платные, push бесплатные), это
  чувствительное разрешение. **Не делать в первой версии**; если понадобится — тот же парсер.

### 1.3 Импорт файла выписки
- Файл выбирается системным диалогом (SAF) или приходит через «Поделиться» в co-shell.
- Подходит для сверки и истории. Требует ручного действия, но редко (раз в месяц).
- Тот же конвейер, что и импорт из Wallet (ARCHITECTURE §8): разбор → сопоставление → предпросмотр
  → импорт без дублей по `importSource` + `importExternalId`.
- CSV/Excel разбирать просто; PDF — тяжело (нужна библиотека, вёрстка меняется) — избегать, если
  банк даёт табличный формат.

### 1.4 Что отвергаем
- **Скрапинг/реверс мобильных API банков** (как делают агрегаторы): нарушает условия банков,
  требует хранить логин/пароль/сессию, ломается при каждом обновлении. Против принципа «надёжно».
- **Accessibility Service** для чтения экрана банковских приложений: хрупко, банки активно
  детектируют и блокируют (антифрод), выглядит как вредонос.
- **Платные агрегаторы** (Plaid/Tink и т.п.): платно, нужен сервер, Ameriabank и Т-Банк
  не поддерживают.

## 2. Ameriabank (Армения)

- **API для физлиц нет.** В тарифах для юрлиц есть «Internet Banking API» как платная услуга;
  в тарифах для физлиц аналога не найдено. Открытый банкинг в Армении законодательно не
  обязателен (срок — не определён), агрегаторы Ameriabank не подключают.
- **Уведомления:** MyAmeria (`am.ameriabank.*` — точный `packageName` проверить на телефоне)
  присылает push об операциях по картам; также есть SMS-оповещения (обычно платные).
  → основной путь — **парсер push MyAmeria**. Валюты: AMD, USD, EUR, RUB — парсер должен
  понимать код валюты в тексте и формат чисел (`1,234.56` / `1 234,56`).
- **Выписка:** выписка по счёту есть в MyAmeria / интернет-банке; в отзывах упоминается выгрузка
  отдельной операции в PDF. Наличие **табличного** формата (Excel/CSV) не подтверждено —
  **проверить у владельца** на реальном аккаунте.
- Нужно от владельца: 5–10 обезличенных текстов push (покупка, перевод, пополнение, снятие,
  покупка в другой валюте, отказ/возврат) и пример файла выписки.

## 3. Bybit

- **Официальный REST API v5**, ключ создаётся в «API Management» с правами **Read-Only**
  (без торговли и вывода) — безопасно хранить на телефоне.
- Полезные эндпоинты (GET/POST с подписью HMAC-SHA256, заголовки `X-BAPI-*`):
  - `GET /v5/account/transaction-log` — журнал Unified-счёта (до 2 лет назад; `accountType=UNIFIED`);
  - `GET /v5/asset/fund-history` — история Funding-счёта (фильтр по типу и периоду);
  - `GET /v5/asset/deposit/query-record`, `.../withdraw/query-record` — ввод/вывод;
  - `POST /v5/card/transaction/query-asset-records` — **операции карты Bybit Card**
    (фильтр по статусу, последним цифрам карты, мерчанту, типу, периоду; MCC-описание в ответе) —
    самое ценное для бюджета, если в семье есть карта Bybit;
  - курсы/конвертации — `fiat-convert`/`convert` history при необходимости.
- Точные поля и лимиты сверить по документации `bybit-exchange.github.io/docs/v5/` при реализации
  (из облачного окружения сайт недоступен — нужно разрешить хост или читать локально).
- **Как вписать в архитектуру без сервера:** синхронизация запускается **на телефоне владельца
  ключа** через WorkManager (например, раз в 6 часов + по кнопке), курсор — время последней
  записи. Ключ хранится только локально (Android Keystore / EncryptedSharedPreferences),
  **в Firestore не попадает**. Полученные операции пишутся в Room → обычная синхронизация.
- Деньги: суммы в криптовалютах — нужны `CurrencyCode` для USDT/BTC/… с правильной точностью
  (USDT — 6 знаков у API, BTC — 8). Строки сумм из API парсить в `Long` минимальных единиц,
  **без `Double`** (золотое правило 1). Обновить `Currencies` и `money-and-currency.md`.
- Риски: Bybit блокирует некоторые регионы/IP (для телефона дома обычно не проблема);
  ключ без привязки к IP по правилам Bybit может иметь ограниченный срок жизни (≈90 дней) —
  проверить, предусмотреть напоминание о перевыпуске.
- Внутренние трейды/фандинг/PnL для семейного бюджета, вероятно, не нужны: импортировать
  только карту, ввод/вывод и, по желанию, итоговый баланс счёта как «счёт co-shell».

## 4. Т-Банк (Россия)

- **API для физлиц по картам/счетам нет.**
  - *T-Invest API* — официальный, по токену, но только брокерский счёт (сделки, купоны,
    дивиденды, пополнения брокерского счёта). Можно подключить отдельно, если нужно учитывать
    инвестиции; для повседневных трат не помогает.
  - *T-API (Open API для бизнеса)* — выписки только для ИП/юрлиц.
  - Старый неофициальный API, которым пользовались Дзен-мани и др., — реверс; в 2026 у сторонних
    приложений жалобы на поломку синхронизации. Не опираемся.
- **Открытые API по стандартам ЦБ:** обязательность для крупнейших банков — с 2026 года,
  стандарт согласий физлиц на доступ к данным счетов — с 01.10.2026; закон о мультибанкинге
  ещё дорабатывался. Доступ будет для **аккредитованных** участников (юрлиц), а не для
  частного приложения → для co-shell **в обозримом будущем не вариант**. Перепроверить через
  год.
- **Уведомления:** бесплатные push Т-Банка сохраняются (платные SMS можно отключить) →
  основной путь — **парсер push Т-Банка** (пакет `com.idamob.tinkoff.android` — проверить).
  В тексте push обычно есть сумма, валюта, мерчант, остаток — остаток полезен для автосверки баланса.
- **Выписка:** справка/выписка по карте за произвольный период формируется в веб-версии и
  приложении (отправка на e-mail, выбор формата). Есть ли CSV/Excel для физлиц сейчас —
  **проверить у владельца**; если только PDF — импорт выписок для Т-Банка отложить.

## 5. Google Pay (Google Wallet)

- **Это не отдельный счёт, а кошелёк токенизированных карт.** Оплата телефоном — это операция по
  карте банка (Ameriabank и др.), она же придёт push-уведомлением банка и попадёт в выписку.
  Значит, Google Pay даёт **не новые деньги, а второй сигнал о той же операции** → обязательна
  дедупликация, иначе каждая покупка задвоится.
- **API нет.** Google Wallet API предназначен для эмитентов (выпуск карт лояльности, билетов,
  пропусков), чтения истории оплат пользователем он не даёт.
- **Уведомления:** после оплаты Google Wallet (`com.google.android.apps.walletnfcrel` — проверить)
  показывает уведомление с суммой, валютой, названием магазина и картой (последние цифры).
  Этим же `NotificationListenerService` его можно читать. Польза:
  - запасной сигнал, если push банка выключены/не пришли или банк шлёт их с задержкой;
  - часто более чистое название магазина и время оплаты;
  - последние 4 цифры карты → какому счёту co-shell принадлежит операция.
- **Takeout** (`takeout.google.com` → Google Pay): ручная выгрузка, судя по источникам — JSON;
  в основном покупки через Google (Play, подписки) и активность Google Pay. Есть ли там
  оплаты картами в магазинах, не подтверждено → **проверить на реальной выгрузке**. Как
  автоматический источник не годится (только вручную).
- **Регионы:** в Армении Google Wallet работает (Ameriabank — с ноября 2022, также ACBA,
  Ardshinbank и др.). В России Google Pay с 2022 года не работает (Visa/Mastercard ушли,
  «Мир» не поддерживается) → для карт Т-Банка этот источник неактуален.
- **Дедупликация с push банка:** совпадение суммы и валюты, время в пределах нескольких минут,
  те же последние цифры карты (если есть в обоих текстах). Приоритет — у записи банка (точная
  сумма в валюте счёта, курс конвертации), из Wallet берём только мерчант, если у банка его нет.
  Если за N минут push банка не пришёл — запись из Wallet идёт во «Входящие» как самостоятельная.

## 6. Рекомендация

Делать **после этапа 4** (синхронизация) отдельным этапом «Автоввод», в таком порядке:

1. **Общий конвейер «Входящие»** (чистый Kotlin): `IncomingTransaction` (источник, внешний id,
   время, `Money`, мерчант, исходный текст) → правила сопоставления счёта/категории
   (мерчант → категория, запоминаются из подтверждений) → экран «Входящие»: подтвердить одним
   тапом / поправить / отклонить. Без автозаписи в бюджет на первых порах.
   Дедупликация: `importSource` + `importExternalId` (для push — хэш пакет+время+сумма+текст;
   плюс нечёткое совпадение с ручными записями: та же сумма ± 1 день).
2. **Парсеры push Т-Банка и Ameriabank** + `NotificationListenerService`. Наибольшая польза:
   покрывает повседневные траты обоих банков.
3. **Уведомления Google Wallet** — дополнительный источник к шагу 2 (тот же сервис, отдельный
   парсер + склейка с push банка). Включать после того, как дедупликация проверена на банковских push.
4. **Bybit API** (read-only ключ, WorkManager на телефоне владельца ключа).
5. **Импорт выписок** CSV/Excel для сверки — переиспользует мастер импорта из этапа 5 (Wallet).

Альтернатива проще и раньше: шаг 2 без экрана «Входящие» — сразу создавать черновик
операции из push. Не рекомендую: ошибка парсера молча портит баланс.

## 7. Что нужно от владельца (открытые вопросы)
- Какими банками пользуется каждый из двоих; есть ли карта **Bybit Card**; нужен ли учёт
  крипто-баланса/инвестиций (Bybit, T-Invest) или только траты.
- Включены ли push об операциях в MyAmeria и Т-Банке; кто платит телефоном через Google Pay и
  какими картами; приходят ли уведомления Google Wallet после оплаты.
- Образцы: по 5–10 обезличенных текстов push каждого банка и Google Wallet (для одной и той же
  покупки — оба уведомления, чтобы проверить склейку) (скриншот шторки подойдёт) и по одному
  файлу выписки — в каких форматах банк реально даёт выгрузку.
