## Контекст
Владелец: «скорость анимаций надо унифицировать, шторка всё ещё дёргается, переходов между экранами не видно;
нужны неоновые, иногда тёплые и насыщенные палитры; анимация для каждого элемента; современная вёрстка;
главное — плавность, простота, удобство».

### Что нашлось в коде (причины)
1. **Скорость не единая.** `tokens/Motion.kt`: три tween (150/250/350 мс) + три кривые; рядом — пружины с разной
   жёсткостью: `Resize/Placement/Turn` (MediumLow×2), нажатие в `motion/TactileModifier.kt` (MediumLow×3,
   отпускание MediumLow с damping 0.45, блик Medium/Low); шторка — свой `tween(LONG_MS)` в `components/Sheet.kt`
   плюс внутренняя анимация Material `ModalBottomSheet`. Итого 8+ разных «темпов».
2. **Шторка дёргается** (`components/Sheet.kt` + `motion/GrowFrom.kt`): одновременно идут **три независимых
   движения** — слайд `ModalBottomSheet` (своя кривая Material), масштаб 0.3 → 1 от нижнего края (tween 350)
   и окно `dialog<…>`-destination (окно диалога + ещё одно окно самого `ModalBottomSheet`). Масштаб от 0.3
   и подъём снизу тянут верхний край в разные стороны → рывок; `onPlaced` пересчитывает точку роста, пока
   шторка едет. Плюс `imePadding` на всей колонке — скачок при появлении клавиатуры.
3. **Переходов не видно** (`app/.../navigation/ScreenTransitions.kt`): кривая `Decelerate (0.05, 0.7, 0.1, 1)`
   проходит ~80 % пути за первые ~60 мс из 350 — глазом это «мгновенно»; уход — `fadeOut` 150 мс; вкладки —
   только растворение и масштаб 0.97. Движение по сути есть, но оно спрятано в первые 3–4 кадра.

Версии позволяют всё нужное: Compose BOM `2026.09.00` (M3 `MotionScheme`, `SharedTransitionLayout`,
`AnchoredDraggable`, `PredictiveBackHandler`), navigation `2.10.2`.

## Шаг 0. Предложение дизайна на согласование (до кода)
HTML-страница (Artifact) с макетами экранов, которые можно пощупать в браузере телефона:
- 3 палитры × светлая/тёмная на одних и тех же экранах (Обзор, Операции, шторка ввода, Счета), переключатель;
- живые демо анимаций (нажатие, шторка, переход экрана, вкладки, перелистывание суммы) на тех же пружинах,
  что пойдут в код (CSS `linear()`-аппроксимация пружин);
- таблица «элемент → анимация».
Владелец выбирает палитру и вёрстку — дальше код. Решения фиксируются в `docs/research/design-questions.md` §7.

## Шаг 1. Единая система движения (основа всего)
`core/designsystem/.../tokens/Motion.kt` переписать на **пружины в двух семействах** (по образцу M3 `MotionScheme`):
- `Motion.Spatial.Fast / Default / Slow` — положение, размер, масштаб (damping 0.9; stiffness ≈ 1400 / 700 / 300).
- `Motion.Effects.Fast / Default / Slow` — прозрачность, цвет (damping 1.0; stiffness ≈ 3800 / 1600 / 800).
- `Motion.Bouncy` — единственная пружина с перелётом (отпускание нажатия, `selectionPop`, «щелчок на место»).
- Таблица соответствий: нажатие → Spatial.Fast; отпускание → Bouncy; раскрытие/размер/список → Spatial.Default;
  экран/шторка → Spatial.Default (жест — Slow «догоняет» палец); растворения → Effects.Default; блик → Effects.Fast.
- Пробросить в M3: `MaterialTheme(motionScheme = CoShellMotionScheme)` в `theme/Theme.kt`, чтобы и встроенные
  компоненты двигались в том же темпе.
- Старые `short()/medium()/enter()/exit()`, `*_MS`, `Standard/Decelerate/Accelerate` удалить; перевести
  `Resize.kt`, `TactileModifier.kt`, `SelectionPop.kt`, `amount/RollingAmountText`, `ScreenTransitions.kt`.
- Тест: расширить `app/.../designsystem/MotionRuleTest` и добавить такой же для `core:designsystem` —
  `tween(`/`spring(`/`CubicBezierEasing` разрешены только в `tokens/Motion.kt`.

## Шаг 2. Новая шторка (без рывков)
Своя реализация `CoShellSheet` вместо `ModalBottomSheet` (остаётся в `components/Sheet.kt`, API тот же —
`CoShellSheet(onClosed) { close -> }`, экраны не меняются):
- **Один источник движения**: `AnchoredDraggableState` (якоря «скрыта/открыта»), анимация — `Motion.Spatial.Default`;
  скрим, скругление и тень вычисляются из того же смещения (в `graphicsLayer`/draw, без рекомпозиций).
- Открытие: подъём снизу + лёгкий масштаб 0.96 → 1 **от точки касания по горизонтали** (вместо 0.3); цвет «+»
  растворяется в фон шторки как сейчас (`colorTintAlpha` из `GrowFrom.kt` переиспользовать).
- Свайп вниз — следует за пальцем 1:1, отпускание — по скорости (fling) к ближайшему якорю.
- Predictive back: `PredictiveBackHandler` — шторка уменьшается до 0.92 и опускается за жестом, отмена — пружиной назад.
- Окно: `dialog<…>` destination оставить (ViewModel и аргументы), но окно без своих анимаций
  (`windowAnimations = 0`, dim 0) и **без второго окна** Material.
- Клавиатура: `imePadding` только на нижней строке «Сохранить» + `WindowInsetsAnimation`-синхронизация
  (`imeNestedScroll` не нужен), форма прокручивается, шторка не прыгает.
- Тесты: чистые функции (выбор якоря по смещению/скорости, прогресс скрима, прогресс predictive back) —
  `core/designsystem/src/test/.../components/SheetMathTest.kt`; `CloseOnce` уже покрыт.
- `GrowFrom.kt`: `GROW_START_SCALE` 0.3 → 0.96, `transformOrigin` считать один раз при старте, не по `onPlaced` в полёте.

## Шаг 3. Заметные переходы между экранами
`app/.../navigation/ScreenTransitions.kt` + `CoShellNavHost.kt`:
- **Вкладки** (Обзор ↔ Операции ↔ Счета ↔ Ещё): «общая ось X» — новый экран въезжает на 1/8 ширины со стороны
  своей вкладки + проявление, старый уезжает в другую сторону + растворение. Направление — по порядку `TopLevel`.
- **Экран из строки/карточки** (Ещё → Категории, Курсы…): контейнер-трансформация через
  `SharedTransitionLayout` вокруг `NavHost` — строка «Ещё» превращается в экран (`sharedBounds` с ключом
  маршрута), фон под ним отходит до 0.94 и темнеет на 8 %. Без касания — сдвиг 1/8 + проявление.
- **Назад** — те же пружины в обратную сторону, predictive back ведёт прогресс (navigation 2.10 это умеет).
- Все на `Motion.Spatial.Default`/`Effects.Default`; растворение старого экрана начинается на 30 % пути
  (не 0), чтобы движение успевали увидеть.
- Нижняя панель при уходе на внутренний экран — уезжает вниз (Spatial.Default), а не исчезает.
- Тест: `ScreenOriginsTest` сохранить; добавить `TabDirectionTest` (направление по порядку вкладок).

## Шаг 4. Анимация каждого элемента (каталог)
| Элемент | Анимация |
|---|---|
| Кнопки, чипы, сегменты, вкладки | тактильная система (как сейчас), темп из Шага 1 |
| «+» (FAB) | нажатие → вырастает в шторку; после «Сохранить» — короткая вспышка-галочка (иконка морфится + → ✓ → +) |
| Активная вкладка | подложка-пилюля **перетекает** между вкладками (одна пилюля, `offset` пружиной), иконка — заливка контур → залитая |
| Главная сумма | `RollingAmountText` (есть) + счётчик «дотикивает» при открытии экрана |
| Карточки на экране | вход лесенкой: проявление + подъём 12 dp, шаг 30 мс, только при первом показе экрана |
| Строки списка | появление/удаление/перестановка — `listItemMotion` (есть); свайп-удаление — строка схлопывается по высоте |
| Липкий заголовок дня | при смене — перелистывание вверх |
| Раскрывашки | `CoShellExpandable` (есть) + стрелка `CoShellExpandIcon` (есть) |
| Переключатель, отметки | бегунок пружиной Bouncy, галочка рисуется штрихом |
| Поля ввода | подпись уезжает вверх, рамка цвета ошибки «встряхивается» 2 раза по горизонтали |
| Снэкбар «Удалено · Отменить» | выезжает из-под панели, полоска времени сжимается |
| Цифры курса/сумм при обновлении | перелистывание только изменившихся разрядов |
| Скелетоны загрузки | мягкое мерцание (один общий `InfiniteTransition` на экран) |
| Смена темы/палитры | круговое раскрытие от переключателя |
Каждая — в компоненте дизайн-системы, экраны ничего не анимируют сами (правило из `motion.md`).

## Шаг 5. Вёрстка экранов (тренды 2025–26, по принципу «проще и под большой палец»)
Общие принципы: крупная типографика итогов; одно главное действие на экран; всё нажимаемое — в нижних 2/3;
**плавающая нижняя панель-пилюля** (отделена от края, сплошная, без размытия — блюр дорог на 120 Гц);
карточки-«бенто» вместо длинных списков на обзоре; шторки снизу вместо новых экранов для коротких задач;
без стекла/неоморфизма (контраст и производительность).
- **Обзор:** сверху — герой-карточка с градиентом палитры: общий баланс крупно, под ним чипы валют отчётов
  (свайп меняет основную). Ниже бенто 2×2: «Траты за месяц» с мини-столбиками по дням, «Доход», «Без курса/
  предупреждения», «Счета» (сколько, сумма). Затем «Последние операции» (5 строк) + «Все →».
- **Операции:** поиск-пилюля сверху (сжимается при прокрутке), строка фильтров-чипов (тип, счёт, период),
  список по дням, у заголовка дня — итог за день справа. Свайп влево — удалить, вправо — дублировать.
- **Шторка ввода:** сумма огромным шрифтом наверху (сразу фокус), под ней сегмент Расход/Доход/Перевод,
  горизонтальная лента категорий (последние первыми), счёт и дата — чипами; «Сохранить» — на всю ширину внизу.
- **Счета:** карточки счетов в цвете счёта (`CoShellCard(tint)`), сверху итог; архив — свёрнутая раскрывашка.
- **Ещё:** сетка 2 колонки плиток с иконками вместо списка; «Настройки» — отдельной строкой внизу.
Вёрстка — после выбора владельца в Шаге 0; код по экрану за PR (`home/` → `transactions/list/` → `transactions/edit/` → `accounts/` → `more/`).
