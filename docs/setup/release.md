# Релиз кнопкой и автомерж PR

## Один раз настроить
1. **Settings → Actions → General → Workflow permissions:** включить «Allow GitHub Actions to create and
   approve pull requests». Без этой настройки workflow не смогут открывать PR.
2. **Issues → Labels → New label:** создать метку `hold`. Ею можно остановить автомерж конкретного PR.
3. **Выпустить один релиз по-старому.** Создайте PR `dev` → `main` и влейте его, или попросите агента
   сделать «релиз». GitHub запускает кнопку Release и автомерж только из копии workflow в `main`,
   поэтому до этого релиза они не работают.

## Как выпустить сборку
**Actions → Release → Run workflow → Run workflow.** Workflow:
1. проверяет, что в `dev` есть новые коммиты и CI на `dev` зелёный (если CI ещё идёт, ждёт его);
2. берёт текст «Что нового» из верхнего раздела `docs/whats-new.md`. Если этот раздел уже выпускался,
   workflow останавливается. Галочка «Выпустить без нового раздела» отключает эту проверку;
3. создаёт PR `dev` → `main` «Release: …» со списком вошедших PR и `Fixes #N` (issue уже закрыты мержем в `dev` — список для истории);
4. вливает PR и запускает CI на `main`, который публикует сборку на телефоны (~6 мин).

С галочкой «Только создать PR» workflow только готовит PR, а влить его можно вручную. Если вливать
запрещает защита ветки, workflow оставит PR открытым и даст на него ссылку.

## Что делают агенты
- Первый push агента открывает **черновик** PR в `dev`. В конце сессии агент снимает черновик, и после
  зелёного CI PR вливается в `dev` сам. Влить PR можно и вручную, как раньше.
- Чтобы PR не вливался автоматически, поставьте на него метку `hold`. Снимете метку — PR вольётся
  (если CI зелёный).
- В `main` ничего не вливается автоматически: туда попадает только то, что выпущено кнопкой Release.
