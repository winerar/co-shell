# Задачи: GitHub Issues и доска

**Где задачи (владелец, 2026-11-10):** все задачи — GitHub Issues репозитория; их статус — метка `status:*`.
Доска владельца — https://github.com/users/winerar/projects/4: на ней все открытые задачи, колонки идут по меткам (Action `tasks.yml`).
В репозитории: `ROADMAP.md` — крупный план и порядок этапов; `STATUS.md` — только передача между
сессиями (что в работе, окружение, последняя сессия). Список дел в STATUS не ведём.

## Метки (`.github/labels.json`, синхронизирует `labels.yml`)
| Статус (ровно один у открытой задачи) | Колонка доски | Когда |
|---|---|---|
| `status:triage` | Разобрать | новый отзыв (ставит `feedback_to_issues.py`) или задача без статуса |
| `status:backlog` | Бэклог | в плане, не скоро |
| `status:next` | Очередь | ближайшее; порядок — ROADMAP §«Порядок после этапа 4» |
| `status:in-progress` | В работе | агент взял в работу (ставит в начале сессии) |
| `status:needs-owner` | Ждёт владельца | вопрос, выбор макета, проверка на телефоне |
| закрыта | Готово | PR с `Fixes #N` влит в `dev` (dev — ветка по умолчанию, GitHub закрывает сам) |

**Тип (владелец, 2026-11-10) — ровно один у каждой задачи** (кроме ещё не разобранных в «Разобрать»):
`type:story` — история, крупная цель пользователя, части — подзадачи (бывш. `epic`); `type:feature` — фича: новая возможность или доработка, в т.ч.
техническая (рефакторинг, замер; бывш. `chore`); `type:bug` — баг: работает не так, как задумано.
`type:question` — вопрос владельцу (бывш. `question`); `type:owner` — делает владелец: проверка на телефоне,
настройка, переезд (бывш. `owner`).
**Отзыв из приложения** — `source:app` (розовая, заголовок «Отзыв: …») поверх типа: приходит в «Разобрать»
без типа, при разборе ставим тип и статус. Ещё: `design` (сначала макет), `hold` (PR не вливать).
Область: `stage:4…9`, `area:design-system|reliability|performance|delivery`. Новую метку — в `labels.json`
(не руками); переименовать — `"from": "старое"`, убрать — `"delete": true` (`labels.yml`).

## Как агент работает с задачами
- **Начало сессии:** `session-start.sh` печатает доску (`scripts/agent/tasks.sh`; `tasks.sh next` — одна колонка).
  Владелец назвал задачу — берём её; иначе — верх «Очереди», вопросы из «Ждёт владельца» — напомнить.
- **Одна задача — одна сессия.** Взял → `status:in-progress` (GitHub MCP `issue_write` `update`, `labels` —
  полный список, старый статус убрать). Подробности, решения, ссылки на макеты — комментарием в задаче.
- **Конец сессии:** в описании PR `Fixes #N` (закроет при мерже) или `Refs #N` (если задача не закончена);
  незаконченную вернуть в `status:next` с комментарием «что осталось». Ждёт владельца → `status:needs-owner`
  и вопрос комментарием (как ответить — одной фразой).
- **Новое по ходу** (хвост, баг, идея) — новая задача с метками статуса и типа, а не строка в STATUS.
  Часть эпика — `issue_write` `create` с `parent_issue_number` (не `sub_issue_write`: огромный ответ).
- **Проверка на телефоне** сделанного — пункт в задаче-чек-листе владельца (`type:owner` + `status:needs-owner`), а не
  открытая задача: задача закрывается мержем.
- Вопрос владельцу — задача `type:question` + `status:needs-owner`; ответ пришёл → решение в ARCHITECTURE/доки, закрыть.

## Доска (GitHub Projects)
- `scripts/ci/project_board.py` (из `tasks.yml`: на события задач и раз в 3 ч): добавляет открытые задачи,
  ставит колонку по метке, закрытые — в «Готово». Колонки создаёт сам (поле Status). Поле «Тип»
  (История/Фича/Баг/Вопрос/Владельцу) — по метке типа, только в одну сторону: группировка и фильтр доски.
- Владелец перетащил карточку → метка меняется на колонку (карточка изменена позже метки); «Готово» у
  открытой задачи — закрывает её. Перетаскивание подхватывается при следующем запуске (≤ 3 ч).
- Нужен секрет **`PROJECT_TOKEN`** — токен владельца с доступом к проектам (инструкция — `docs/setup/tasks-board.md`).
  Без него шаг пропускается с предупреждением, метки работают.
- Агенту доска напрямую недоступна (нет инструментов Projects) — только метки.
