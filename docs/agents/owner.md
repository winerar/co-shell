# Владелец и его предпочтения

Стабильные факты о проекте и о том, как владелец хочет работать. Меняются редко.

## Контекст продукта
- Приложение пока для своей семьи (2 пользователя), но **станет публичным** (2026-11-23): рынки — Аргентина, Армения, РФ; цель — покрыть расходы на содержание и разработку и получить небольшой доход; платные функции — гипотеза «бесплатное ядро + подписка на облачное» (`docs/research/monetization.md`).
- Оба телефона — **Android**: Xiaomi 14 и Xiaomi 15 (владелец 2026-11-21: встроенный Gemini Nano на них недоступен — рассчитываем на скачиваемую модель, #587). iPhone может появиться → держим готовность к KMP (`kmp-readiness.md`).
- Архитектура должна быть **бесплатной и надёжной**: никаких платных тарифов и своих серверов (для семьи; при публичном запуске расходы на пользователя — в `monetization.md`).
  Исключение (2026-11-22, #635): облачный разбор заметок — API Claude по факту (баланс ~$5) через бесплатный Cloudflare Worker, по желанию и после разбора на телефоне.
- Семья живёт в **Аргентине** (траты в ARS, USD), доход в **AMD**, есть счета в RUB.
  Важно для этапа 2 (доступность Firebase) и этапа 3 (источник курсов должен знать ARS и AMD).
- Частый случай: **оплата USDT-картой покупок в песо** (чек в ARS, списано USDT) — ввод в двух валютах
  важнее остальной мультивалютности. Курс песо — **официальный** (blue/MEP не нужен).
- **Много валют**; основную валюту отчётов можно менять, можно смотреть в нескольких сразу.
- **Пока не публикуем** в Google Play/RuStore (установка APK + самообновление), но **публикация возможна** (2026-11-14):
  тексты и решения — без привязки к нашей семье и внутренней кухне (`texts.md`).
- Сейчас семья пользуется **Wallet (BudgetBakers)** → нужен импорт истории (ROADMAP этап 5).
- Название: co-shell ≈ «кошел(ёк)» / «общий кошелёк».

## Принципы приложения (отзывы владельца)
- **Открыл и пользуйся** (#427, 2026-11-15): готово к работе для человека, который никогда не вёл бюджет, —
  без обязательной настройки, пустые экраны подсказывают следующий шаг. Первый запуск — #353 (после 1.0).
- **Привить любовь к бюджету** (#513, 2026-11-18): обучение — мягкое и дружелюбное, для человека, который ни разу не вёл бюджет, но хочет
  начать: «Первые шаги» + одиночные подсказки, без тура и без вины; повтор — «Ещё → Приложение». Подсказки обновляем вместе с интерфейсом (`hints.md`).
- **Единообразие** (2026-11-20): одни и те же данные (счёт, категория, операция, сумма) в разных местах выглядят одинаково — как на их основном экране; выбор счёта в шторке ввода = строки «Счетов».
- **Гибкость** (#428, 2026-11-15): настроек достаточно, но без излишеств; каждая понятна по названию и находится
  там, где её ищут (путь «Ещё → …»). Новая настройка — только с ответом «кому и зачем», иначе — разумное значение по умолчанию.

## Как работать с владельцем
- Общение — **на русском**, кратко, с рекомендацией, а не только списком вариантов.
- Принятые решения не переобсуждать без новой причины.
- **Задачи для владельца — всегда на доску** (2026-11-11): задача `type:owner` + `status:needs-owner` с пошаговой
  инструкцией, прямыми ссылками и готовым кодом для вставки прямо в задаче (правило — `tasks.md`).
- **Предупреждать, когда сессия разрослась** и токены тратятся быстро, — владелец начнёт новую.
- **В конце каждой сессии** сохранять состояние в репозиторий и **самому создавать PR** в `dev` (подтверждено 2026-11-16: «создавай по окончании работы всегда»; черновик уже есть — обновить и снять «draft»);
  в `main` (= выкатка на телефоны) — **только по команде «релиз»** (`workflow.md`, «Git»).
- Код — **разбит на небольшие логические файлы** с понятной структурой, удобной для изучения
  человеком и агентом (правила — `project-structure.md` §«Файлы»).
- Владелец **не знает Kotlin**: объяснять результат словами, без разбора кода. Где возможно — делать
  **универсальные переиспользуемые компоненты** вместо копий (`project-structure.md` §«Переиспользование»).
- Приложение должно быть **лёгким, экономным к памяти, быстрым и плавным** (анимации без рывков
  на экранах 90/120 Гц) — правила в `performance.md`.
- В будущем — **своя дизайн-система**, на которую переезжают все экраны (ROADMAP §«Дизайн-система»).
- **Перед любыми визуальными изменениями — сначала визуальные примеры** (макет, варианты), код — только
  после «ок» владельца (2026-11-10; правило — `workflow.md` §«Визуальные изменения»).
- Держать `AGENTS.md` и `docs/agents/*` актуальными и небольшими (правила размера — в `AGENTS.md`).
- **Выбор макетов — страницей-опросом** с превью и полем правок (2026-11-13; как — `workflow.md`).
- Макеты — **с длинными списками** (20–30+ элементов): работа с большим количеством должна быть удобной (2026-11-11).
- **Доска — источник истины** (2026-11-16): интерфейс меняется только после правки макета и «ок»; доски экранов, воркфлоу и компонентов всегда соответствуют приложению (`workflow.md` §«Доска — источник истины»).
- **Всё — строго из утверждённого набора компонентов** (2026-11-15, #367; «крайне важно»): нет нужного, даже самого
  малого, — макет, утверждение, на доску «Компоненты», потом код. Покрыто тестами (`components.md` §«Утверждённый набор»).
- **Карточки-герои — с градиентом темы** и на макетах, и в коде (2026-11-12, #277).
- **Вкладки на всех экранах листаются свайпом**, не только нижние (2026-11-11).
- **Редакторы и создание — без прокрутки** (отзыв #290, 2026-11-13): всё помещается на экран, разные сущности явно
  отделены друг от друга. **Суммы — только своей клавиатурой** с `+` и `−` (#291); системная — для текста.
- **Светлая тема: яркие палитры — ярче, нежные остаются нежными, меньше чёрного** (2026-11-18; `design-system.md` §«Цвета»).
- **Тексты — лаконичные, дружелюбные, уважительные** (2026-11-15): новичку в бюджете понятно, что где и как, почему так
  называется и где найти нужное — во всём интерфейсе (`texts.md` §«Как писать»).
